# 錯誤捕捉

## Summary
殼掛上 Dart 端的全域錯誤處理，把未捕捉的錯誤先存成待送紀錄（跨重啟保留、最多 50 筆），再派給 App 註冊的錯誤回報接口。網頁安裝主控台日誌時取回尚未確認的紀錄、寫入它設定的檔案，寫成功才確認，殼才刪除；之後的新錯誤由殼逐筆推送。接口預留給 Crashlytics 之類的服務，殼本身不依賴它們。原生崩潰與被系統終止尚未涵蓋。

## 運作方式

### 一筆 Dart 錯誤的去向

這張圖回答：Dart 端發生未捕捉錯誤後，怎麼最後出現在網頁設定的檔案？

```json diagram id=錯誤去向
{
  "type": "sequence", "title": "一筆 Dart 錯誤的去向", "desc": "先存待送紀錄與派給回報接口；網頁取回或接收後寫檔，成功才確認刪除",
  "actors": ["Dart", "殼", "網頁"],
  "steps": [
    {"from": "Dart", "to": "殼", "text": "未捕捉錯誤"},
    {"from": "殼", "to": "殼", "text": "存成待送紀錄"},
    {"from": "殼", "to": "殼", "text": "派給回報接口"},
    {"from": "網頁", "to": "殼", "text": "取回未確認紀錄"},
    {"from": "殼", "to": "網頁", "text": "最多 50 筆", "reply": true},
    {"from": "殼", "to": "網頁", "text": "新紀錄逐筆推送", "emit": "crash_reports"},
    {"from": "網頁", "to": "網頁", "text": "寫入目標檔案"},
    {"from": "網頁", "to": "殼", "text": "寫成功才確認"},
    {"from": "殼", "to": "殼", "text": "刪除待送紀錄"}
  ]
}
```

![一筆 Dart 錯誤的去向](error-capture.錯誤去向.svg)

1. 框架錯誤與非同步未捕捉錯誤各有一個處理入口，原本的處理照常執行。
2. 錯誤先存成待送紀錄；存檔先寫暫存再改名，避免寫到一半被終止留下壞檔。
3. 同時派給所有已註冊的錯誤回報接口，其中一個丟例外不影響其他。
4. 網頁安裝時取回所有未確認的紀錄，殼從此刻起推送新紀錄。
5. 事件在網頁未連線時被丟棄也不會遺失，下次取回時仍在待送紀錄裡。
6. 網頁寫成功才確認，殼只刪除格式合法的 id，避免被要求刪除任意檔案。

## 規則

| 規則 | 說明 |
|---|---|
| 錯誤來源 | 框架錯誤（非致命）、非同步未捕捉錯誤（致命）；網頁錯誤只派給接口，不進待送紀錄 |
| 待送紀錄位置 | App 支援目錄下的待送資料夾，每筆一個檔案 |
| 上限 | 50 筆，超過丟棄最舊；訊息 8 KiB、堆疊 32 KiB，超過截斷 |
| 保留 | 跨重啟保留；壞檔在讀取時刪除 |
| 回報接口 | 公開的抽象類別，啟動時傳入；殼不內建任何實作，也不依賴 Firebase |
| 網頁端不安裝時 | 殼不推送，紀錄留在待送資料夾，數量受上限約束 |
| 尚未涵蓋 | 原生崩潰、無回應、被系統終止、渲染進程崩潰 |
