# 日誌檔

## Summary
殼把網頁送來的日誌行追加寫入 App 的檔案，檔名由 key 與寫入當下的本地日期組成，跨午夜自動換新檔，不需要任何排程。網頁可指定檔案的根目錄來源、子目錄與檔名；殼嚴格驗證這些值，不合法或本平台不支援時拒絕，不改寫到其他位置。沒指定時寫到 App 內部的預設日誌目錄。殼自己內部的警告也寫到預設目錄，不受網頁指定的目標影響。預設目錄有保留天數與總容量上限，避免檔案越積越多。

![一行日誌如何落檔](log-file.落檔.svg)

1. 網頁送來層級、訊息，以及選填的寫入目標。
2. 沒有目標時，用預設目錄與目前設定的 key。
3. 有目標時，先驗證子目錄與檔名；不合法立即拒絕，不碰檔案系統。
4. 依目標的根目錄來源取得實際目錄，本平台取不到時拒絕。
5. 每次寫入都重新取本地日期組出檔名，所以跨午夜的下一筆自然落到新檔。
6. 追加一行並立即寫入磁碟，格式為時間、層級、訊息。

## 規則

| 規則 | 說明 |
|---|---|
| 根目錄來源 | 內部（預設）、文件、快取、暫存、外部；外部僅 Android，為 App 專屬目錄，不需權限 |
| 子目錄 | 相對路徑、以斜線分段；每段只允許英數、點、底線、連字號；不得為空段或上層；最多 8 段、總長 128 |
| 檔名 | 英數、點、底線、連字號，1 至 64 字；省略時用目前的 key |
| 不可用的來源 | 回報不支援並拒絕，不改寫到別的來源 |
| 檔名格式 | key 或檔名，加底線與八位日期，副檔名為日誌 |
| 預設位置 | 內部目錄下的日誌資料夾，預設 key 為 app |
| 管理功能 | 列表、讀取、寫入、刪除、取得目錄只針對預設位置，不涵蓋網頁指定的其他位置 |
| 保留策略 | 只清理預設位置：預設保留 14 天、總容量 20 MiB，超過就刪最舊的；今天的檔案永遠保留；App 可調整或設為不限 |
| 清理時機 | 啟動時與每次建立當日新檔時各一次，不加排程；清理失敗不影響寫入 |
| 網頁指定的位置 | 不在保留策略內，由網頁自行管理 |

## 錯誤與提示

| 文案 | 條件 | 處置 |
|---|---|---|
| 目標不合法 | 子目錄或檔名不符規則 | 修正目標；該筆不寫 |
| 來源不可用 | 本平台不支援該根目錄來源 | 改用其他來源 |
