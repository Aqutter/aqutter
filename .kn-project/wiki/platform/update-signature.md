# 更新簽章

## Summary
殼可以在編譯期內置 Ed25519 公鑰，只接受簽署端用私鑰簽過的網頁包；簽章綁定版本與網頁包的雜湊，缺少、格式錯或驗證不過就拒絕更新並保留現行網頁包。沒設公鑰時維持只看雜湊的原有行為。公鑰只來自編譯期，網頁無法更改；私鑰只存在簽署端。安裝包的更新由系統比對簽署憑證，不在此機制內。

![一個網頁包如何通過驗證](update-signature.驗證流程.svg)

1. 殼依版本查詢的回應下載網頁包。
2. 沒有公鑰時只看雜湊：回應有雜湊就驗，沒有就不驗，簽章欄位被忽略。
3. 有公鑰時，雜湊與簽章缺一不可；缺任何一個就拒絕。
4. 先用實際下載的位元組算出雜湊，與回應宣告的相比，不符就拒絕。
5. 再用公鑰清單驗簽章，任一把通過即可；全部不通過就拒絕。
6. 驗證在解包之前完成，拒絕時不動現行網頁包，也不留下待套用的內容。
7. 失敗的處理與下載失敗相同：一般模式續用舊版，嚴格模式進入無法確認版本的阻擋頁。

## 規則

| 規則 | 說明 |
|---|---|
| 演算法 | Ed25519；簽章為 Base64，解碼後 64 位元組 |
| 簽章訊息 | 固定前綴、版本、小寫雜湊各占一行，以換行結尾；簽署端與殼必須逐位元組相同 |
| 綁定版本 | 版本被簽進訊息，舊網頁包不能換上新版本號重放 |
| 公鑰來源 | 只有編譯期設定，逗號分隔可多把；網頁與更新設定的修改入口都碰不到它 |
| 多把公鑰 | 任一把驗證通過即可，用於金鑰輪替 |
| 公鑰不合法 | 不是合法 Base64 或不是 32 位元組就在啟動時報錯，不靜默忽略 |
| 沒設公鑰 | 與簽章功能出現之前完全相同 |
| 私鑰 | 只在簽署端，不進 App、不進編譯期設定、不進版控 |
| 種子網頁包 | 隨 App 打包，視為可信，不驗簽章 |
| 安裝包更新 | 不在此機制內，Android 安裝時由系統比對簽署憑證 |

## 錯誤與提示

| 文案 | 條件 | 處置 |
|---|---|---|
| 簽章缺失 | 設了公鑰，回應沒有簽章 | 簽署網頁包並把簽章放進版本查詢回應 |
| 簽章驗證失敗 | 簽章與版本、雜湊或公鑰不符 | 確認簽署用的私鑰與 App 內的公鑰是一對、版本與雜湊未被改動 |
| 雜湊缺失 | 設了公鑰，回應沒有雜湊 | 在版本查詢回應補上雜湊 |
| 雜湊不符 | 下載的位元組與宣告的雜湊不同 | 重新發佈網頁包，確認檔案未被改動 |
